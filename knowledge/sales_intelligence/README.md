# IDIEM Sales Intelligence v2

## Objetivo
Fuente complementaria de conocimiento para el sistema de contenidos de IDIEM en Claude Code, construida desde las presentaciones comerciales de las células/segmentos.

Este paquete NO reemplaza las definiciones oficiales de células, reglas de clasificación, brochures validados ni reglas editoriales existentes.

## Jerarquía obligatoria de conocimiento

1. Reglas oficiales de células y clasificación
2. Reglas editoriales / sistema de contenidos
3. Servicios y brochures validados
4. Sales Intelligence (este paquete)
5. Casos / evidencias
6. Fuentes externas

Si existe una contradicción, siempre prevalece la fuente superior.

## Estados de publicación

### SAFE
Concepto general utilizable para ideación y redacción, siempre respetando las reglas editoriales.

### VERIFY
Dato que requiere validación humana o fuente vigente antes de publicarse:
- cifras
- porcentajes
- montos
- fechas
- cronogramas
- proyectos en curso
- número de proyectos/clientes
- claims de cobertura
- certificaciones
- referencias específicas
- afirmaciones legales
- tiempos de respuesta/servicio
- resultados cuantificados

### INTERNAL
Información útil para razonamiento comercial, pero que no debe copiarse literalmente como mensaje público.

### DO_NOT_PUBLISH
Placeholder, texto incompleto, contradicción, afirmación no validada o contenido expresamente excluido.

## Patrón editorial recomendado

PROBLEMA / NECESIDAD
→ IMPACTO EN EL MANDANTE
→ CAPACIDAD O SERVICIO IDIEM
→ EVIDENCIA / CASO (si está validado)
→ CTA

El objetivo es evitar contenidos construidos únicamente como catálogo de servicios.

## Uso recomendado

1. Resolver primero la célula según las reglas oficiales.
2. Consultar la ficha de Sales Intelligence pertinente.
3. Seleccionar un `pain_point` o `business_need`.
4. Cruzarlo con servicios/capacidades previamente validados.
5. Incorporar proof points solo si están habilitados.
6. Si interviene un elemento `VERIFY`, marcar la pieza para revisión humana.
7. Nunca publicar elementos `DO_NOT_PUBLISH`.
8. Mantener trazabilidad de qué ficha y fuente originaron el contenido.
